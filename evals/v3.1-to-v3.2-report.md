# Classifier v3.1 → v3.2 — eval report

**Prompt change.** v3.2 adds an "Honest 6-digit fallback" rule: when the deciding distinction between candidate 8-digit lines is an attribute **genuinely absent from the input description** (unit value tier, fiber-content %, dimensional threshold, etc.), the classifier returns the 6-digit subheading zero-padded (`XXXX.XX.00.00`), sets `precision_level = "6"`, keeps `confidence = "high"`, and lists the specific missing attribute. v3.2 also explicitly states this is NOT an escape hatch: when the deciding attribute IS in the description, the model must use it.

**Schema change.** Added `precision_level: enum("10","8","6")` to `ClassificationOutput`, default `"10"` so v3.1-style outputs still parse.

**Scorer change.** `evals/run-classifier-eval.ts` now reports 6/8/10-digit accuracy separately. Top-1 @ 6-digit credits both 8-correct predictions and honest 6-digit fallbacks (`precision_level=="6"` AND code ends `.00.00` AND `missing_inputs_for_precision` is non-empty AND 6-digit prefix matches expected).

The full prompt diff is in `/tmp/v3.1-to-v3.2.diff` and the bottom of this file.

## Movement at 8-digit

- **5 improvements** (v3.1 wrong @ 8 → v3.2 correct @ 8):
  - `3304.99.50` sunscreen — v3.1 picked `3304.91.00`, v3.2 picked correct
  - `3926.90.75` pool float — v3.1 routed to `9506.99.55` (toy), v3.2 stays in plastics
  - `6505.00.20` cotton baseball cap — v3.1 `6505.00.25`, v3.2 correct
  - `8504.40.95` USB wall charger — v3.1 `8504.40.70`, v3.2 correct
  - `8421.21.00` water filter pitcher — v3.1 routed to `3924.10.20`, v3.2 correct
- **7 regressions** (v3.1 correct @ 8 → v3.2 wrong @ 8):
  - `4202.21.60` handbag (no value stated) — **honest fallback to `4202.21.00`** (v3.1 lucky-guessed `.90`, in accept_set)
  - `4202.31.60` leather wallet (no value stated) — **honest fallback to `4202.31.00`** (v3.1 picked `.60` exactly, by default)
  - `4910.00.20` wall calendar → v3.2 picked `4910.00.60`
  - `7615.10.30` aluminum nonstick pan → v3.2 picked `7615.10.71`
  - `8215.99.50` BBQ spatula → v3.2 picked `8215.99.35`
  - `8508.11.00` robot vacuum → v3.2 picked `8508.60.00` (wrong subheading)
  - `9404.90.20` decorative throw pillow → v3.2 picked `6304.99.40` (wrong chapter)

Net at 8-digit: +5 − 7 = **−2 cases**. Of the 7 regressions, **2 are honest fallbacks** (handbag, wallet) where v3.2 is correct at 6-digit and would have been correct at 8-digit if the broker filled in unit value. The remaining 5 regressions are genuine classifier drift — different attention to different parts of the prompt resulting in different 8-digit picks. These are not "harder cases that the model gave up on"; they're the same cases, picked differently.

## "Moves from wrong-8-digit guess to correct-6-digit fallback"

**Zero.** The 2 honest fallbacks in v3.2 (handbag generic, leather wallet) were both cases where v3.1 happened to be 8-digit-correct: handbag because the case is `disputed` with accept_set `{4202.21.60, 4202.21.90}` and v3.1 picked `.90` (in the accept set); wallet because v3.1 defaulted to `4202.31.60` which happens to be the gold answer. So the fallback didn't rescue any genuine v3.1 failure on the gold set — it converted lucky-guess 8-credit into honest 6-credit on 2 cases.

This is consistent with the prompt design: the fallback only fires when the model **recognizes** it cannot tell. Of the 41 v3.1 8-digit failures, 0 were recognized by v3.2 as 6-digit-fallback candidates. The model is over-confident in the same direction in both versions.

**Calibration warning.** v3.2 moves cases from `medium` to `high` (n=64 → n=78, n_medium 30 → 15) while high-confidence accuracy is unchanged (65.6 → 65.4). The cases the model is newly confident about are no better than the cases it was already confident about — fine. But the cases it's still calling `medium` are now much worse (46.7% → 20.0%). The medium bucket is now the residual where the model has flagged genuine ambiguity but didn't fall back to 6-digit. That bucket has shrunk to harder material.

This isn't a degradation in the cases the broker would actually trust — the high-confidence floor held. But it does mean **don't filter on "medium and above" as a quality proxy** in v3.2; the medium bucket has different semantics now.

## Should v3.2 ship?

**Pros:**
- 6-digit accuracy preserved (57.7%) with explicit honest-fallback semantics for the 4202 value-tier cases that the gold set already accepts as ambiguous.
- Citation grounding up 4.2 pp.
- Refund-finder precision up ~5 pp with same recall.
- Schema now carries `precision_level`, making the classifier's commitment explicit to broker review tooling.

**Cons:**
- 8-digit accuracy down 2 pp (5 of 7 regressions are not honest fallbacks; they're classifier drift).
- Honest fallback under-activates (only 2 cases out of 41 v3.1 8-digit failures).
- Medium-confidence bucket has shrunk and become noisier (47% → 20% accuracy at 8-digit). Downstream consumers that filter on confidence should be aware.

**Recommendation: ship v3.2.** The 8-digit drop is small, the calibration floor held, the refund finder marginally improved, and the schema-level precision_level field is durable infrastructure for honest abstention going forward — even if this prompt doesn't yet fully exercise it. A future v3.3 should focus on **broadening fallback activation**: the model should recognize value-tier / fiber-content / dimensional-threshold splits more aggressively and abstain when those attributes are absent, instead of guessing.

## Prompt diff (v3.1 → v3.2)

Saved at `/tmp/v3.1-to-v3.2.diff`. Core additions:

- New "Honest 6-digit fallback (when the input genuinely cannot support the 8-digit pick)" section after the Specificity Rule. Includes mechanics, "when this applies", "when this DOES NOT apply (do not use as an escape hatch)", a worked example where the fallback applies, and a worked counter-example where it does NOT.
- Output section updated to document `precision_level`, with explicit constraints (when "6", `hts_code` must end `.00.00` AND `missing_inputs_for_precision` must be non-empty).
- "Default to medium" guidance reworked into "prefer 6-digit fallback over medium-confidence guessing" for the specific cases where it applies (value-tier, single-attribute splits).
